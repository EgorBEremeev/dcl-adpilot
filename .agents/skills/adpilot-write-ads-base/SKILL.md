# Базовые карточки adpilot

Используй этот skill, когда нужно написать или обновить базовые поля заголовка и описания в товарном YAML-файле adpilot-каталога.

## Источники и порядок работы

1. Прочитай товарный YAML и `category_fingerprint.md`, если он существует в той же директории.
2. Проверь наличие `attributes.yaml` в той же директории, и если он существет:
  - Прочитай его - это схема атрибутов категории данного товара
  - Выполни проверку полноты экстракции: сопоставь каждое поле схемы с `draft_record` из товарного YAML и уже заполненными значениями, найди факты, которые ещё не перенесены в YAML, и дополни только существующие поля схемы. При неоднозначной маркировке сохрани исходную формулировку или оставь поле незаполненным; не создавай, не переименовывай и не переопределяй поля самой схемы в рамках написания карточки.
3. Считай фактическими только значения из товарного YAML, `draft_record` и явно предоставленных пользователем данных. Не выводи технические характеристики, совместимость, сертификацию, безопасность, исправность или технический осмотр из одного названия категории.
4. Если отсутствие факта влияет на покупку или безопасность, либо задание допускает разные варианты, задай короткий уточняющий вопрос до публикации. Если карточку нужно подготовить несмотря на пробелы, явно укажи, что именно не подтверждено.
5. Напиши заголовок и описание на языке, заданном карточкой или пользователем. Заголовок должен кратко содержать тип товара, ключевую характеристику и важный сценарий/комплектность, если они подтверждены.
6. Сохрани исходный YAML-формат и кодировку UTF-8 без BOM. Не меняй поля, не относящиеся к карточке.
7. Учитывай целевую платформу публикации. Для OLX, bazar.bg и ALO.bg тег `<br>` не используй: по умолчанию сохраняй абзацы, заголовки и пункты обычными нативными переносами строк внутри YAML-блока. Используй `<br>` только если целевая платформа поддерживает чистый HTML (например, eBay) или пользователь явно этого попросил.
8. Для размеров используй обычную латинскую `x` с пробелами (`160 x 65 см`), а не Unicode-символ умножения `×`.

## Формат описания

Собери описание по [references/description-template.md](references/description-template.md). Там находятся порядок блоков, допустимый HTML и примеры готовых карточек. Выбирай вариант блоков по фактам конкретного товара; не добавляй рекламные или технические утверждения, которых нет в источниках.

В многострочном YAML каждый видимый абзац, заголовок и пункт списка размещай на отдельной физической строке. Для OLX, bazar.bg и ALO.bg физические переносы строк YAML являются основным способом форматирования, поэтому `<br>` полностью опускай. Для платформ с чистым HTML `<br>` допускается только в соответствии с их форматом публикации и не должен дублировать нативные переносы.

## Перед сохранением

Перед сохранением проверь согласованность текста с YAML, полноту переноса подтвержденных характеристик, отсутствие неподтвержденных утверждений, корректность HTML и наличие обязательных для шаблона блоков. Если ключ содержит `<model-id>`, замени его фактическим идентификатором модели генерации, сохраняя паттерн каталога.
